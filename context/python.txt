py-numba 0.66.0 (hash /gahuud2, %gcc14, JIT CPU/GPU): `spack load py-numba` bare resuelve

  Para loops de Python puro con millones de iteraciones secuenciales (integradores ODE/SDE
  paso a paso, Monte Carlo iterativo), agregar @njit a las funciones del loop da speedups
  reales de 50-100x+ (validado: integrador de Heun, 500k pasos, 8.9s → 0.096s, ~93x). Primera
  opción ante un loop `for i in range(N)` con N grande y trabajo por iteración chico.
  ⚠ CRÍTICO — NO sugerir `multiprocessing`/chunking por tiempo para integración SECUENCIAL
  (donde el estado en el paso i depende del paso i-1, ej. Euler/Heun/Runge-Kutta): partir el
  rango temporal en chunks independientes con `Pool` arrancando cada uno desde
  `initial_condition` NO reconstruye la trayectoria real — cada chunk sería una simulación
  distinta empezando de cero. Válido solo si las iteraciones son independientes entre sí (ej.
  barrido de parámetros). Para integración secuencial, Numba (@njit) es la opción correcta.

LAMMPS metal puro (Cu, Al, Ni, Au...): USAR SIEMPRE esta plantilla de input, sin read_data ni archivos .data a mano ni scripts python que generen posiciones
(átomos = 4*nx*ny*nz en fcc; 1000 átomos = 5x5x10 celdas; Cu a=3.615, Al 4.05, Ni 3.52, Au 4.08; 1 solo tipo de átomo, sin bonds/angles):

    pair_style eam / pair_coeff * * ${LAMMPS_DIR}/share/lammps/potentials/Cu_u3.eam   (en el input va la RUTA COMPLETA; "potential" NO es un comando LAMMPS)
    velocity all create 300.0 12345 dist gaussian / timestep 0.001 / thermo 100 / fix 1 all nve / run N

LAMMPS input: NUNCA create_atoms random → átomos solapados → "Lost atoms". SIEMPRE lattice fcc.
NUNCA thermo después de run — va ANTES.
NUNCA inventar ruta de potencial (pair_coeff) tipo "/mnt/cpu-data/shared/lammps_potentials/" —
  NO EXISTE. Los potenciales YA VIENEN con LAMMPS: $LAMMPS_DIR/share/lammps/potentials/
  (256 archivos, ej: Al_jnp.eam, AlCu.eam.alloy). Si no está ahí, avisar y sugerir NIST/openkim.org.
LAMMPS con duración pedida en tiempo real ("por 10 minutos"): ese tiempo es el #SBATCH --time y un tope de pared, NO una cantidad de pasos.
  NUNCA decir "10 minutos = N pasos". Poner `timer timeout 00:09:30 every 1000` antes de `run` (corte ordenado antes del --time) y un `run` grande
  (ej. 10000000); aclarar que el número de pasos alcanzados depende de la velocidad y se ve en el log.
units lj: parámetros adimensionales. Si el usuario pide K o Å → usar units real/metal.
units lj: pe/ke del log ya son POR ÁTOMO (norm yes default) — NUNCA dividir por N en el análisis.
Líquido LJ (Ar 94 K, 0.0211 átomos/Å3): lattice fcc 5.745 (NUNCA sc/5.256 = gas), units real: pair_coeff 1 1 0.2381 3.405 (kcal/mol, no eV), mass 39.948, timestep 5.0 (fs), 1 fix nvt (temp 94.0 94.0 500.0) y luego 1 fix nve. Átomos 4n^3: 14^3 -> 10976 (usar para ~10000 y avisar). D: compute msd all msd / fix 9 all vector 100 c_msd[4] / variable D equal slope(f_9)/6/(100*dt) (Å2/fs, x0.1 = cm2/s; Ar ~2e-5 cm2/s).
Difusión D por MSD: promediar ≥10 semillas (-var seed N, ${seed} en input quoteado) — 1 trayectoria da error ~100%. msd NO es keyword de thermo_style: compute msd_all all msd (SIN com yes) + c_msd_all[4].
Bug CUDA error 34: export LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libcuda.so.1
log.lammps: NUNCA np.loadtxt() directo — el log tiene texto. Parsear así: `in_run=False; for line in f: if "Step" in line and "Temp" in line: in_run=True; continue; if in_run and "Loop" in line: break; if in_run: data.append(line.split())` — NO buscar cadena exacta (el log tiene espacios múltiples entre columnas).

Convertir un job LAMMPS de CPU a GPU (validado real 28/9, corrida real en A100 con
  "Using acceleration for lj/cut" + Device Time Info real en el log):
  1. sbatch: --partition=gpu o gpu-scavenger (según QOS), agregar --gres=gpu:N, WORKDIR pasa
     de /mnt/cpu-data/$USER/ a /mnt/gpu-data/$USER/ (regla de WORKDIR por partición: gpu usa gpu-data).
  2. spack load lammps-gpu (o hash /3z7zdg3) en vez de lammps-cpu, + LD_PRELOAD=libcuda.so.1
     (ver [NO TOCAR] en core.txt — sin esto crash real confirmado).
  3. Agregar "-sf gpu -pk gpu $NGPU" al comando lmp (NGPU = GPUs pedidas con --gres). El input
     .lmp NO necesita editarse — "-sf gpu" auto-sufija los pair_style compatibles en runtime,
     "pair_style lj/cut" corre como "lj/cut/gpu" sin tocar una línea del script.
  4. ⚠ CRÍTICO: no todos los pair_style tienen variante /gpu — este build (paquetes instalados:
     FEP GPU KSPACE MANYBODY MOLECULE OPENMP RIGID SCAFACOS, confirmado con "lmp -h") solo
     acelera los pair_style que aparecen ahí con sufijo /gpu (lj/cut, eam, eam/alloy, eam/fs,
     morse, buck, born, coul/long, coul/cut, coul/debye, coul/dsf, lj/charmm/coul/charmm,
     lj/cut/coul/*, sw, table, tersoff, tersoff/mod, tersoff/zbl, vashishta, yukawa, zbl, soft,
     lj/expand, npt/nve/nvt con sufijo gpu). Si el script usa un pair_style que NO está en esa
     lista (reax/c, airebo, comb, meam/spline, sw/mod, etc.) NO hay aceleración GPU disponible
     para ese potencial en este build — avisar al usuario en vez de prometer un speedup que no
     va a pasar, no inventar un pair_style/gpu que no existe acá.
  5. mpirun sigue siendo obligatorio (NUNCA correr lmp directo sin mpirun, ni para -h — cuelga
     en silencio, confirmado en vivo).

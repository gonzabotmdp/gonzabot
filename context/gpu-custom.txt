NVHPC 26.5 (actualizado 22/8, hash /qpe3nuq — la 24.9 vieja ya no existe): NVHPC_DIR=$($SPACK location -i /qpe3nuq 2>/dev/null); nvc/nvc++/nvfortran; OpenACC: nvc -acc -gpu=cc80; CUDA: nvcc -arch=sm_80

CUDA/C/Fortran, proyecto MULTI-ARCHIVO (codigo.cu + compile.sbatch + run.sbatch + submit.sh), no sbatch gigante. Nombrar cada bloque en el texto previo ("compile.sbatch:") — se guardan con /saveall. Cambio puntual → modificar SOLO ese archivo, NO regenerar el resto.
  compile y run COMPARTEN dir fijo: DIR=/mnt/gpu-data/$USER/proyecto (sin $SLURM_JOB_ID — deben coincidir; gpu NO ve cpu-data). Ambos --partition=gpu.
  Dependencia SOLO en submit.sh: JID=$(sbatch --parsable compile.sbatch); sbatch --dependency=afterok:$JID run.sbatch. NUNCA #SBATCH --dependency en el .sbatch.

CUDA kernels numéricos: verificar estabilidad. Ecuaciones de onda (SWE, acústica): Leapfrog (NO Forward Euler — inestable para todo k). CFL: c*dt/dx < 1/sqrt(dims). Forward Euler → NaN o ruido exponencial en 100-1000 pasos.

NCCL: NO INSTALADO (sacado 22/8). Si un usuario pide multi-GPU con NCCL, avisar que no está disponible — alternativa: MPI.jl (Julia) o comunicación manual entre procesos.

GPU (partition=gpu) CON CUDA: incluye su propia LLVM parcheada — LLVM_JL NO existe/NO hace falta.
  CUDA_DIR=$($SPACK location -i /okkjtu2 2>/dev/null); export PATH=$CUDA_DIR/bin:$PATH; export LD_LIBRARY_PATH=$CUDA_DIR/lib64:$LD_LIBRARY_PATH
  CRÍTICO — requisito de una sola vez por usuario: si $HOME/.julia/environments/v1.11/LocalPreferences.toml NO tiene "[CUDA_Runtime_jll]\nlocal = true", CUDA.jl intenta bajar el runtime de internet y el nodo GPU NO tiene salida a internet → el job se CUELGA EN SILENCIO (sin error, sin output) hasta agotar el time limit. Incluir siempre en el sbatch, antes de correr Julia:
    mkdir -p $HOME/.julia/environments/v1.11
    grep -q "CUDA_Runtime_jll" $HOME/.julia/environments/v1.11/LocalPreferences.toml 2>/dev/null || printf '[CUDA_Runtime_jll]\nlocal = true\n' >> $HOME/.julia/environments/v1.11/LocalPreferences.toml
  Julia SIN CUDA en nodo GPU (CPU-only dentro de un job GPU) si hace falta: mismo patrón pero sin CUDA_DIR ni el bloque LocalPreferences.
  ${JULIA_BIN} --threads=12 script.jl
  @cuda: SIEMPRE función separada, NO begin...end inline. Alternativa simple: c = a .+ b; CUDA.synchronize()
  Multi-GPU: MPI.jl + CUDA.device!(rank % 4)
  Julia: script .jl con heredoc en $WORKDIR. NO $JULIA_BIN -e '...' (comillas anidadas).

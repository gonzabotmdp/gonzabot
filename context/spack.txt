RECONOCIMIENTO DE HERRAMIENTAS:
  pw.x / pw.x -in → QUANTUM ESPRESSO (QE). NO LAMMPS. Aplicar reglas de dft-qe.txt.
  lmp / lmp -in   → LAMMPS. Aplicar reglas de md-sim.txt.
  gmx / gmx_mpi   → GROMACS. Aplicar reglas de md-sim.txt.

HARDWARE: 16 nodos CPU (quad-11/12/33/34-n01..n04) — TODOS IDÉNTICOS. NO hace falta pinear
  --nodelist a un nodo específico por rendimiento — cualquier nodo de la partición cpu da el
  mismo resultado. Si un --nodelist puntual está lleno/ocupado (ver squeue), sugerir sacar el
  --nodelist o cambiar a otro nodo cpu cualquiera, no hay pérdida de performance por el cambio.

NUNCA "module load/avail/spider" en ningún sbatch — este cluster NO tiene Lmod, "module" no es un comando válido en los nodos. SIEMPRE spack: $SPACK --no-locks location -i /hash (ver hash por software en el segmento de cada uno).

SPACK en sbatch: los jobs batch NO heredan funciones de shell.
  SIEMPRE agregar antes de spack load, EN ESTE ORDEN:
  export SPACK_USER_CONFIG_PATH=/apps/local/spack/spack-2026b/user-config
  source /apps/local/spack/spack-2026b/spack/share/spack/setup-env.sh
  spack env activate /apps/local/spack/spack-2026b/spack/var/spack/environments/rebuild-full
  eval $(spack load --sh <paquete>)   # ej: lammps, gromacs, cp2k, r, root, quantum-espresso, openfoam, julia — sin hash, resuelve solo
  ⚠ NUNCA mezclar con rutas del store viejo (/usr/share/spack). NUNCA inventar el path si el paquete no está en la lista de abajo — avisar que no está validado ahí todavía.

STORE NUEVO (spack-2026b): store default para todos los usuarios (el viejo queda legacy/respaldo). VTK y paraview: SACADOS a propósito — NO ofrecerlos, no están en ningún store (nota completa en python.txt). Octave: sin GUI/gnuplot todavía.
  "spack load lammps/gromacs/fftw/netcdf-c/openblas/py-pandas" (sin hash, nombre pelado) ya
